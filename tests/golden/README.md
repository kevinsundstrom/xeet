# Goldens

Every file here was produced by a Chrome oracle run against X's real stylesheet
and markup, never by xeet. Each one has a `<name>.stamp.json` sidecar recording
the upstream snapshot, the browser (Playwright's Chromium, the one
`tools/oracle/browser.mjs` launches) and a hash of the oracle harness;
`node tools/ship/golden-stamp.mjs --check` (a job in every pull request) rejects
a golden that changed without a new stamp.

That rule exists because the usual failure mode of a rendering project is
"update the snapshots" until the tests are green and the output has quietly
drifted from the site. If a golden disagrees with xeet, either the oracle run is
stale or xeet is wrong; editing the golden is neither.

## What may be committed

X's text and pixels are X's property (raw captures live in a private store and
the repository holds only a lockfile of hashes). So:

| File | Contents | Committed? |
|---|---|---|
| `text.json` | our **synthetic** fuzz/coverage strings and Chrome's line boxes for them | yes — the text is generated by us, the geometry is a measurement |
| `e2e.json` | per-post verdicts, height deltas, line counts, pixel ratios, and a SHA-256 of the differing line | yes — counts, numbers, hashes; no text, no pixels |
| `raster/*.png` | Chrome screenshots of real posts | **no** — private store only |
| corpus-derived text goldens | X's post text | **no** — private store only |

That is why the text oracle runs with `--no-corpus`: it is not an optimisation,
it is what makes the golden committable.

## Regenerating

```sh
node tools/ship/golden-capture.mjs --kind text   # runs the oracle, writes the golden, stamps it
node tools/ship/golden-capture.mjs --kind e2e --report tmp/e2e-full.json
node tools/ship/golden-stamp.mjs --check         # what CI runs
```

A stamp can only be made from the oracle's own log, and only with the Chrome in
`tools/ship/oracle-pin.json`; bumping that pin is an explicit oracle-bump
decision, never a routine pull request's.

`tools/ship/parity-check.mjs` compares xeet against `text.json` with no Chrome
and no network, so the layout gate runs on every pull request.
